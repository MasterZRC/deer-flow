## 评分标准（我会按这个批改）

- **能引用 `文件:行号`** 的答案，比"大意对"的答案值钱得多。
- 说出**为什么这样设计**（不这样会坏在哪），比复述"它做了什么"值钱得多。
- 答不出来时直接写 `C`（不知道），**不要猜**——猜中会让我低估你的盲区，这才是真正的损失。
  - `A` = 敢下注，能拿出证据
  - `B` = 大概是这样，但不确定细节
  - `C` = 不知道 / 只有模糊印象

## Q1 —— 准入（Admission）

一个 `POST` 请求进来，到**第一行业务代码**之间发生了什么？

要求说清：
- 路由在哪个文件、哪个 handler 函数（给 `file:line`）；
- `RunManager` 在真正跑 agent 之前做了哪几件事，按顺序列出（记录落库、幂等键、同线程互斥、状态机）；
- **状态名按顺序写全**（`pending` → … → 终止态有哪些）；
- 这个请求里，客户端**能**影响哪些字段、**绝对不能**影响哪些字段？（提示：想一想 run-context 的信任边界，哪些 key 会被服务端无条件覆盖。）

置信度：`A / B / C`

## Q2 —— 执行（Execution）

`run_agent()` / `make_lead_agent()` / `build_middlewares()` 三者的职责边界分别是什么？

要求说清：
- 图在哪里被编译、middleware 链在哪里被装配（给文件）；
- **按真实执行顺序**列出 middleware 链（至少前 8 个），每个一行说明它"挡在模型调用前做什么"；
- 三者中谁负责注入 config 与「服务端拥有的 runtime context」？为什么要区分"服务端拥有"和"客户端可传"？

一个 LangGraph 的 step，怎么变成浏览器收到的一帧 SSE？

## Q4 —— 终止（Termination）

一次 run 有哪些结束方式？每种方式下**谁**决定最终状态、**什么**被持久化？

要求说清：
- 枚举终止路径（正常成功、报错、取消、取消并回滚、interrupted 中断、超时…）；
- 每条路径下 run 记录 / event store / journal / delivery receipt 各写了什么；
- **取消并回滚**在 `full` 与 `delta` 两种 checkpoint 模式下行为不同，**判断走哪条路的那个谓词是什么**？（这是本仓库最容易踩的雷，答不出很正常，但要能说出"我去哪找"）

置信度：`A / B / C`

## Q5 —— 契约（Contracts）

一个新的贡献者**绝对不能**破坏哪些契约？

要求说清：
- harness ↔ app 的单向依赖：方向是什么、被哪个测试钉死（给文件）；
- 前端依赖的 SSE 事件名/形状，与后端产出的位置是否一一对应？举一个具体的；
- run/thread 的状态词表定义在哪个文件？为什么它必须和另一处保持一致？
- 选一个你说"最容易被无意破坏"的契约，说明**破坏后会在哪一层暴露**（CI？运行时？用户界面？）
